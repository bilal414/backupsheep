# BackupSheep Brand Guidelines

## Brand at a glance

**BackupSheep** is the open-source backup and recovery control plane.

**Brand idea:** Own the way back.

**Promise:** Backups you control. Restores you can trust.

**Essence:** Quietly vigilant.

**Archetype:** Guardian × Engineer.

**Selected visual concept:** The Sentinel Sheep.

---

## 1. What the brand stands for

BackupSheep exists to make recovery an owned capability. It gives operators a common operational layer across websites, databases, cloud infrastructure, and storage while preserving appropriate source-native backup and recovery mechanisms.

The brand therefore communicates four things in this order:

1. **Recovery** — there is a known way back.
2. **Control** — the operator owns the management layer and destinations.
3. **Evidence** — success and failure are visible and explainable.
4. **Coverage** — heterogeneous infrastructure can be managed consistently.

---

## 2. Personality

BackupSheep is:

- calm;
- technically competent;
- transparent;
- independent;
- approachable;
- prepared.

BackupSheep is not:

- alarmist;
- cute for the sake of cuteness;
- corporate and impersonal;
- hacker-themed;
- futuristic/AI-coded;
- sarcastic during incidents;
- overconfident about safety.

---

## 3. Logo

The final identity uses a geometric Sentinel Sheep symbol paired with the BackupSheep wordmark.

### Required variants

- horizontal primary;
- horizontal compact;
- stacked;
- symbol;
- wordmark;
- monochrome dark;
- monochrome reverse.

### Usage

Use the full lockup when brand recognition matters and horizontal space permits. Use the symbol alone for favicon, app icon, repository avatar, social avatar, and very small product placements.

### Do not

- stretch or skew;
- recolor arbitrarily;
- place over visually noisy imagery;
- add shadows/glows to the master mark;
- put the sheep inside a shield;
- add a cloud or database glyph to explain the category;
- animate the production logo continuously;
- use mascot artwork as a substitute for the core symbol.

---

## 4. Color

Primary brand palette:

- **Night** `#111827`
- **Night Deep** `#080D14`
- **Wool** `#F7F4EC`
- **Wool White** `#FFFDF8`
- **Meadow** `#27AE78`
- **Meadow Dark** `#167A53`
- **Sky** `#5AA7C8`
- **Stone** `#667085`

Operational states use separate semantic colors for success, warning, danger, and information.

Do not use the brand accent as the sole signal of success.

---

## 5. Typography

Recommended:

- **Manrope** for marketing/display.
- **Inter** for product and documentation.
- System monospace for code and technical identifiers.

Use strong, spacious headlines and restrained body typography. The product console prioritizes density and legibility over display personality.

---

## 6. Mascot

The Sentinel is a character extension of the brand mark.

### Character

The Sentinel is watchful, grounded, prepared, and subtly expressive. It is not a cartoon sidekick.

### Appropriate uses

- onboarding;
- empty states;
- community;
- contributor pages;
- release graphics;
- documentation covers;
- social content;
- marketing illustration.

### Inappropriate uses

- destructive confirmation;
- failed backup/restore alerts;
- security incidents;
- urgent warnings;
- dense data tables;
- every product page.

---

## 7. Messaging

### Permanent hierarchy

1. **Own the way back.** — master idea.
2. **The open-source backup and recovery control plane.** — category.
3. **Backups you control. Restores you can trust.** — promise.
4. **Bring every backup under your own roof.** — campaign.
5. **Your server. Your storage. Your recovery.** — close.

### Four message pillars

- Own the recovery path.
- One operating model, native mechanisms.
- Trust the evidence.
- Know the way back.

---

## 8. Voice

Write like a calm infrastructure operator explaining the system to another competent operator.

Prefer specific statements:

> Backup completed. Two copies are available.

Over generic reassurance:

> Your data is safe!

Prefer actionable failure copy:

> Backup failed while transferring files. No completed archive was recorded.

Over mascot humor:

> Oops! A sheep wandered off.

---

## 9. Visual composition

### Marketing

- generous negative space;
- strong headline hierarchy;
- one focal visual;
- dark/light contrast;
- small technical details as proof;
- provider logos grouped consistently;
- restrained mascot presence.

### Product

- quiet surfaces;
- obvious operational hierarchy;
- compact status information;
- clear primary action;
- semantic state colors;
- brand character concentrated in navigation, empty states, and onboarding.

### Documentation

- diagrams before decorative illustration;
- canonical Source → BackupSheep → Destination → Recovery model;
- consistent code formatting;
- screenshots with enough context to orient the reader.

---

## 10. Provider logos

Provider identity remains provider identity.

- Use official marks where licensing permits.
- Do not recolor provider logos into Meadow.
- Normalize visual size using a consistent container.
- Give provider marks neutral background treatment when contrast requires it.
- Do not imply partnership or endorsement unless one exists.

---

## 11. Brand architecture

**BackupSheep** — master brand/product.

**BackupSheep Console** — web UI.

**BackupSheep Server** — deployed application.

**BackupSheep Workers** — execution workers.

**BackupSheep API** — API.

Potential future managed service: **BackupSheep Managed**.

Optional community concept: **The Flock**.

Do not create sheep-themed names for technical objects.

---

## 12. Claim discipline

Brand trust depends on literal accuracy.

- Distinguish the historical SaaS user count from current open-source adoption.
- Distinguish website/database console restores from provider-native cloud recovery.
- Say that copies go to destinations configured by the user rather than claiming data never leaves the user's infrastructure.
- Describe implemented security and retention controls rather than broad “secure” absolutes.
- Describe beta status where release maturity is relevant.

---

## 13. Open-source expression

Open source should feel like a product advantage, not a disclaimer.

Show:

- GPLv3 clearly;
- source access;
- contribution path;
- transparent architecture;
- reproducible deployment;
- public roadmap/issues where appropriate.

Avoid visual language that makes “open source” synonymous with unfinished, hobby-only, or unsupported.

---

## 14. Quality bar

Before publishing any brand asset, ask:

1. Is it immediately clear this relates to infrastructure backup/recovery?
2. Does it feel calm rather than fear-driven?
3. Is the sheep memorable without becoming childish?
4. Does it remain legible and recognizable at the intended size?
5. Are technical claims literally supportable?
6. Does it fit the same system as the console and documentation?
7. Would an agency trust this interface with client infrastructure?

If the answer to any critical question is no, revise before release.
