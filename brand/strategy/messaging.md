## Narrative

Modern infrastructure is rarely in one place. Websites, databases, cloud resources, and stored copies often live in different systems. Individual tasks may be automated while the recovery plan remains fragmented.

BackupSheep brings that recovery surface into one open, self-hosted operating layer. It coordinates the appropriate backup mechanism for each source, sends copies where the operator chooses, and keeps the path back visible.

The software runs in the operator's environment. Backup data goes only to destinations the operator configures. Recovery is treated as part of the product rather than an afterthought.

## Feature naming

Prefer descriptive operational names such as:

- Incremental website backups
- Protected copy
- Immutable retention
- Storage lifecycle
- Restore history
- Activity log
- Storage cost estimate

Do not invent sheep-themed names for technical features. Clarity wins.

## Claim discipline

- Keep the original SaaS user count explicitly historical.
- Distinguish website/database console restores from provider-native cloud recovery.
- Say copies go to destinations configured by the operator rather than claiming all data remains local.
- Describe implemented reliability and protection behavior literally.
- Keep beta status visible where maturity expectations matter.
