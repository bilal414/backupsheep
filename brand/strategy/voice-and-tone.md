# BackupSheep Voice and Tone

## Voice

BackupSheep sounds **calm, precise, transparent, capable, and subtly warm**.

Write for competent operators. Explain what happened and what comes next without dramatizing infrastructure work or hiding behind jargon.

## Traits

### Calm

Make incidents understandable rather than emotional.

### Precise

Name the source, run, destination, state, and next action when they matter.

### Transparent

Explain provider-specific behavior and limitations rather than implying every workload behaves identically.

### Capable

Use technically credible language without unnecessary complexity.

### Warm

Use personality in onboarding, empty states, community material, and celebrations. Keep high-consequence actions operational.

## Tone by context

| Context | Tone | Example |
| --- | --- | --- |
| Marketing | Confident and clear | Own the way back. |
| Onboarding | Reassuring and instructional | Connect the first system you want BackupSheep to protect. |
| Normal status | Compact and operational | Three copies completed. |
| Failure | Direct and actionable | The transfer stopped before the archive completed. Review the run log. |
| Restore | Deliberate and calm | This restore may overwrite files that differ from the selected backup. |
| Documentation | Exact | Cloud snapshots are recovered through the provider's native workflow. |
| Community | Warm and collaborative | Fork it. Run it. Improve it. |

## Preferred vocabulary

- protect
- recover
- verify
- copy
- destination
- run
- restore
- recovery path
- protected resource
- source-native
- user-controlled

Use broad reassurance sparingly. Prefer observable state.

## Writing rules

1. Lead with the operational outcome, then explain mechanism.
2. Prefer short declarative sentences for status and error copy.
3. Use provider and protocol names accurately.
4. Keep humor away from destructive actions and recovery confirmation.
5. Avoid excessive exclamation marks.
6. Do not use disaster imagery or fear as the default sales device.
7. Explain limitations where the user makes a decision.
8. Use sentence case by default.
9. Prefer evidence over generic reassurance.
10. Keep technical terminology consistent across UI and docs.

## Sheep metaphor

The sheep metaphor is an accent, not the application's vocabulary.

Appropriate:

- mascot artwork;
- community graphics;
- contributor content;
- empty states;
- launch campaigns;
- subtle visual motifs around watching, returning, and a flock of resources.

Inappropriate:

- renaming backups as sheep;
- calling destinations barns;
- calling schedules feeding times;
- using mascot jokes during operational failures;
- replacing technical labels with farm metaphors.

## Naming architecture

**BackupSheep** — master brand and product. Always one word with capital B and S.

**BackupSheep Console** — browser management interface.

**BackupSheep Server** — deployed self-hosted application.

**BackupSheep Workers** — background execution services.

**BackupSheep API** — REST API.

**BackupSheep Self-Hosted** — descriptive edition label only when comparison is necessary.

Do not rename the current product “Community Edition” while no commercial edition requires that distinction.

### Future managed offering

Preferred name: **BackupSheep Managed**.

This describes the operating model without suggesting that BackupSheep must become the storage destination.

### Community

**The Flock** is reserved as an optional community concept for newsletters, contributor recognition, community calls, or sponsor programs. It is not a product object model.

## Product terminology

“Node” may remain an internal technical term. In public marketing and onboarding, prefer **source** or **protected resource** where that improves comprehension.

Use **destination** for a place where a copy is stored.

Use **run** for an execution of a backup or restore.

Use **copy** for one stored instance at a destination.

Use **restore** for the operation and **recovery** for the broader capability/outcome.

## Examples

Instead of:

> Never worry about your backups again!

Use:

> Know what is protected, where the copies live, and how to get back.

Instead of:

> Oops! Your backup sheep wandered off.

Use:

> Backup did not complete during file transfer. Review the run log before retrying.

Instead of:

> Your data is safe!

Use:

> Backup completed. Copies are available on the configured destinations.

Instead of:

> Create a node.

Use:

> Choose the first resource you want to protect.

Instead of:

> Go back in time.

Use:

> Restore the selected backup to the source.
